# MTransfer — Техническое задание / PRD (RU)

**Версия:** 0.1 (черновик) · **Статус:** приватный репозиторий, разовый личный перенос → затем публичный релиз (вычищенный)
**Стек:** Python CLI + крошечный веб-UI (FastAPI + MusicKit JS) · **ОС:** в первую очередь Windows · **Авторизация:** только токены/куки

---

## 1. Проблема и цель

У Яндекс Музыки нет официального экспорта библиотеки. У Apple Music есть официальный путь импорта (MusicKit), но нужны Developer JWT + авторизованный пользователем Media User Token, а моста со стороны Яндекса нет. Вручную переносить сотни/тысячи лайков нереально.

**Цель:** небольшая, «одноразовая» программа/сервис, переносящая мои лайки из Яндекс Музыки в Apple Music (медиатека + датированный плейлист), с отчётом о сопоставлении и ручной проверкой несопоставленного.

**Не цель:** поддерживаемый многопользовательский SaaS, скачивание/загрузка аудиофайлов, масштабный скрапинг с нарушением ToS.

## 2. Пользователи

v1 — один пользователь (я). После открытия кода: любой мигрант Яндекс→Apple с базовыми навыками CLI/браузера.

## 3. Объём работ

### В объёме (v1)

- **F1 — Авторизация Яндекса:** OAuth-токен (`oauth.yandex.ru`, вставляется вручную) и/или импорт cookie из залогиненного Chrome. Токен — в переменной окружения / `.env`, в git не попадает.
- **F2 — Экспорт из Яндекса:** лайкнутые треки (название, исполнители[], альбом, длительность_мс, ISRC если есть, id трека Яндекса, обложка). Выход: `data/yandex_favorites.json` + `.csv`. Прогресс + resume при обрыве.
- **F3 — Нормализация:** каноническая схема `Track`; lower/trim/схлопывание пунктуации; обработка `feat./feat/ft.`; кириллица сохраняется; длительность округляется до секунд.
- **F4 — Матчинг с каталогом Apple:** поиск каждого трека через iTunes Search API (без авторизации, троттлинг ~20 запр/мин) с фолбэком на catalog search Apple (нужен Developer JWT). Скоринг: точный ISRC = автопринятие (1.0); нормализованный текст + длительность Δ≤3с = высокий (≥0.85); только текст = средний (на ручную проверку). Выход: `matched_tracks.json`, `unmatched_tracks.json`, `migration_report.txt` со статистикой и корзинами уверенности.
- **F5 — Экран проверки в веб-UI:** таблица совпадений (зелёный/жёлтый/красный по уверенности), чекбоксы включить/пропустить, ручной поиск-и-выбор для несопоставленного, превью `--dry-run`.
- **F6 — Авторизация Apple:** Developer JWT автоизвлекается из JS-бандла `beta.music.apple.com` (скрипт `extract_apple_tokens.py --save`); Media User Token — через MusicKit JS `authorize()` в веб-UI (предпочтительно, без копипасты cookie) с запасным вариантом вставки cookie (`.apple_music_token`). Токены живут недели–месяцы; переизвлечение документировано.
- **F7 — Импорт в Apple:** создание плейлиста `Yandex Import YYYY-MM-DD`; добавление сопоставленных Apple ID; добавление в библиотеку / простановка лайков; идемпотентность (пропуск существующих, безопасный перезапуск); прогресс-бар; resume `--from N`; лог ошибок по трекам; `--dry-run`.
- **F8 — Отчёт и повтор:** финальный отчёт (импортировано/пропущено/ошибки + причины); CSV несопоставленного для ручного добавления; `retry --only-failed`.

### Вне объёма (v1)

Плейлисты кроме лайков (v2), подписки на альбомы/артистов, скачивание MP3,scheduled-синк, мультиаккаунт, мобильное приложение, платный Apple Developer flow.

## 4. Пользовательский сценарий (веб-UI)

1. **Подключение Яндекса** → вставить OAuth-токен (или «импорт cookie из Chrome») → [Проверить] показывает `N лайков найдено` → [Экспорт] с прогрессом.
2. **Матчинг** → автозапуск с прогрессом → таблица: ✅ высокое / ⚠️ проверить / ❌ не найдено; корректировка выбора; [Продолжить].
3. **Подключение Apple** → [Войти через Apple Music] (MusicKit `authorize()`) → показывает аккаунт/сторфронт → [Dry-run] показывает «будет добавлено X».
4. **Перенос** → прогресс-бар → финальный экран: импортировано / пропущено / ошибки + ссылка на плейлист + [Скачать unmatched.csv] [Повторить ошибки].

CLI дублирует каждый шаг (`export → match → extract-tokens → import --dry-run → import`).

## 5. Функциональные требования

- FR1: экспорт обязан захватывать все поля, нужные для матчинга (название/артисты/альбом/длительность/ISRC).
- FR2: матчер не должен молча терять треки — каждый вход оказывается в matched или unmatched с причиной + скором.
- FR3: пропускная способность матчера ≥ ~15 треков/мин с учётом лимитов; полный прогон возобновляемый.
- FR4: dry-run не делает ни одной мутации библиотеки Apple и печатает точный список pending-изменений.
- FR5: импорт идемпотентен — повторный запуск не плодит дубликаты.
- FR6: секреты (токены, куки, выгрузки) не пишутся в отслеживаемые git-пути; `.gitignore` обязателен; `--verify` скрывает значения токенов в логах.
- FR7: все сетевые сбои — ретраи с backoff (3 попытки), затем запись в failed с причиной.

## 6. Модель данных

```jsonc
// Track (канонический)
{ "source": "yandex", "yandex_id": "123", "title": "…", "artists": ["…"],
  "album": "…", "duration_ms": 213000, "isrc": "…", "cover_url": "…" }
// MatchResult
{ "yandex_id": "123", "apple_id": "456", "confidence": 0.93,
  "method": "isrc|text+duration|manual", "candidates": [...] }
// Job
{ "job_id": "uuid", "stage": "export|match|import", "total": N, "done": M,
  "failed": [...], "created_at": "…" }
```

Файлы: `data/yandex_favorites.{json,csv}`, `data/matched_tracks.json`, `data/unmatched_tracks.json`, `data/migration_report.txt`, `data/job.json` (указатель resume). Модули `src/`: `export_yandex.py`, `match_apple.py`, `import_apple.py`, `extract_apple_tokens.py`, `web.py` (+ `static/` — страница с MusicKit JS).

## 7. Интеграция Apple Music (конкретные эндпоинты)

- Dev JWT: извлекается из бандла `beta.music.apple.com` (временный, TTL в месяцы).
- User token: `musicKit.authorize()` в браузере (предпочтительно) или значение cookie `media-user-token`.
- Поиск: `GET https://itunes.apple.com/search?term=&media=music&entity=song&limit=5` (без авторизации) или `GET https://amp-api.music.apple.com/v1/catalog/{storefront}/search` (нужны оба токена).
- Библиотека: `POST /v1/me/library/playlists` (создание), `POST /v1/me/library/playlists/{id}/tracks` (добавление), `PUT /v1/me/ratings/songs` (лайк). Сторфронт — из user token (`/v1/me/storefront`).
- Квоты: троттлинг поиска (~пауза 3с), батчи добавления (≤50), backoff при 429.

## 8. Интеграция Яндекса (конкретно)

- Авторизация A: OAuth implicit flow `https://oauth.yandex.ru/authorize?response_type=token&client_id=<app>` → токен в hash URL → `YANDEX_MUSIC_TOKEN`.
- Авторизация B: сбор cookie из залогиненного профиля Chrome (документировано, opt-in).
- API: `api.music.yandex.ru` (или Python-библиотека `yandex-music`) — пагинация `likes/tracks`; поля по §6. Паузы между запросами; при 401 — сообщение «перелогиньтесь».

## 9. Требования к UX

- Двуязычные строки UI (переключатель EN/RU); один экран на этап; крупный статус («312 / 1050 сопоставлено»); цвета уверенности; одна primary-кнопка на экран; поля токенов с маскировкой `password`; ссылки на доки на каждом шаге авторизации.

## 10. Нефункциональные требования

- Windows 10/11 + Python 3.10+; только `pip install -r requirements.txt`.
- Без фоновых сервисов; job-файл SQLite/JSON; безопасный Ctrl-C.
- Логи в консоль + `data/run.log`; токены заредактированы.
- Полный перенос ~1–2к лайков за < 2ч wall-clock (в основном троттled-матчинг).

## 11. Риски и митигация

| Риск | Митигация |
|---|---|
| Поменяется неофициальный API/куки Яндекса | пиним версию `yandex-music`; запасной cookie-путь; понятная ошибка переавторизации |
| Протухание Dev JWT / user token | `extract --save --verify`; кнопка переавторизации MusicKit |
| Треки RU-каталога/кириллицы отсутствуют в каталоге Apple | unmatched CSV + ручной выбор в UI; импорт не блокируется |
| Рейт-лимиты 429 | паузы + backoff + resume |
| Случайная утечка токена в публичный доступ | gitignore + pre-commit проверка; приватность до вычистки |

## 12. Критерии приёмки (v1 готов)

- [ ] Экспорт даёт JSON+CSV, количество сходится с лайками Яндекса (± явно перечисленные пропуски).
- [ ] Каждый трек — в matched или unmatched со скором+причиной.
- [ ] Dry-run ничего не меняет; реальный прогон создаёт датированный плейлист с треками + лайками.
- [ ] Повторный запуск не добавляет дубликатов; resume после kill работает.
- [ ] Есть финальный отчёт + unmatched.csv; секретов в git нет (`git log --all -p` чист).
- [ ] Публичным репозиторий становится только после вычистки токенов + готовности доков.

## 13. Майлстоуны

M1 CLI export+match → M2 импорт в Apple (dry-run) → M3 веб-UI + MusicKit authorize → M4 мой полный перенос + отчёт → M5 вычистка + публичный релиз.
